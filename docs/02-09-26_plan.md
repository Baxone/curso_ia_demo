## Ambigüedades resueltas por el usuario

1. **Cabeceras incompletas:** se tratan como error de formato, mismo tratamiento que CA-4 (400 Bad Request). *(Actualizado por spec v1.1 — ver más abajo: `category` queda excluida de esta regla.)*
2. **Campo `file` ausente:** es obligatorio; si no se envía, el endpoint responde con un mensaje avisando de ello (CA-5.4).
3. **Mensajes exactos de error (400/413):** se dejan a criterio del Desarrollador en la fase de implementación.

## Actualización — spec v1.1: `category` pasa a opcional

`specs/transaction-import.md` se actualizó (02-09-2026, ver `doc/inventario/02-09-26_inventario_category.md`) para que `category` deje de ser obligatoria. Cambios aplicados a este plan:

- **TASK-4 / CA-4.5:** las cabeceras obligatorias que provocan error de formato son ahora solo `date`, `description` y `amount`. La ausencia de la columna `category` ya no se trata como error.

**Pendiente de asignar a una task (no resuelto en esta edición):** la nueva `CA-8` de la spec (fila con `category` vacía o ausente → válida, normalizada a `"Sin categoría"`) todavía no está cubierta por ninguna task. Además, `src/validators/csv.validator.js` (línea 54, `validateRow`) sigue tratando `category` como campo obligatorio por fila — con el código actual, una fila con `category` vacío se seguiría rechazando, lo que contradice CA-8. Todas las tasks de este plan marcan ese fichero como "NO tocar", así que resolver CA-8 exige o bien modificar `csv.validator.js` (fuera del scope actual) o bien aplicar la normalización a `"Sin categoría"` en el servicio *antes* de invocar `validateRow`, de forma que la fila nunca llegue vacía de categoría al validador. Requiere decisión antes de pasar a Tester/Desarrollador.
