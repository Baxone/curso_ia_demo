# Plan de tasks — POST /transactions/import

**Spec origen:** `specs/transaction-import.md`
**Generado:** 2026-09-01

---

```
TASK-1: Validador de formato CSV
Descripción: Implementa las reglas de validación de bajo nivel: verificación de headers obligatorios (date, description, category, amount), validación de una fila individual (campos vacíos, amount numérico), y validación de tamaño de fichero. Son funciones puras, sin acceso a red ni al request.
Crea/modifica:
  - src/validators/csv.validator.js: contiene las funciones de validación reutilizadas por el servicio y la ruta
NO tocar:
  - src/routes/, src/services/, config/, .env
Criterios de aceptación propios:
  - CA-1.1: función que valida que los headers del CSV sean exactamente date, description, category, amount → si no, indica formato inválido (soporta CA-4)
  - CA-1.2: función que valida una fila y devuelve motivo de rechazo "campo '<X>' vacío en línea N" cuando cualquier columna obligatoria está vacía (soporta CA-2)
  - CA-1.3: función que valida que amount sea un decimal parseable (acepta negativos, positivos y cero) y devuelve "amount inválido: '<valor>'" si no lo es (soporta CA-6)
  - CA-1.4: función que valida que el tamaño del fichero no supere 10 MB, invocable antes de parsear contenido (soporta CA-5)
Depende de: ninguna
```

```
TASK-2: Servicio de procesamiento de transacciones
Descripción: Orquesta el parseo completo del CSV usando las funciones de src/validators/csv.validator.js, clasifica cada fila en válida o rechazada, y calcula total_by_category y top_5 sobre las filas válidas.
Crea/modifica:
  - src/services/transaction.service.js: lógica de negocio — parseo fila a fila, agregación por categoría, cálculo de top_5
NO tocar:
  - src/routes/, src/validators/csv.validator.js (solo se consume, no se modifica su contrato)
Criterios de aceptación propios:
  - CA-2.1: dado un CSV con headers correctos y N filas válidas, devuelve valid_count=N, rejected=[], total_by_category y top_5 correctos (CA-1)
  - CA-2.2: dado un CSV con filas mezcladas válidas/inválidas, clasifica correctamente y el número de línea reportado empieza en 2 para la primera fila de datos (CA-2, CA-6)
  - CA-2.3: total_by_category solo suma importes de filas válidas, agrupadas por categoría
  - CA-2.4: con 1000 filas incluyendo empates de amount, top_5 devuelve exactamente 5 elementos y ninguno es menor que una fila no incluida (CA-7)
  - CA-2.5: dado un CSV con solo headers (sin filas de datos), devuelve valid_count=0, rejected=[], total_by_category={}, top_5=[] (CA-3)
Depende de: TASK-1
```

```
TASK-3: Endpoint POST /transactions/import
Descripción: Define la ruta, recibe el fichero multipart con multer, valida que sea CSV y que no supere 10MB ANTES de procesar contenido, delega el procesamiento a transaction.service.js y traduce el resultado o los errores de validación en la respuesta HTTP.
Crea/modifica:
  - src/routes/transactions.js: solo routing — define ruta, llama al servicio, devuelve respuesta (sin lógica de negocio)
NO tocar:
  - src/services/transaction.service.js (solo se invoca), src/validators/csv.validator.js
Criterios de aceptación propios:
  - CA-3.1: fichero no-CSV (PDF, imagen, texto sin comas) → 400 con body.message describiendo el error de formato (CA-4)
  - CA-3.2: fichero >10MB → 413 con body.message explicando el límite, comprobado antes de leer/parsear el contenido (CA-5)
  - CA-3.3: fichero CSV válido → 200 con el body devuelto por el servicio, sin transformación de datos en la ruta
Depende de: TASK-2
```

```
TASK-4: Bootstrap de la aplicación Express
Descripción: Crea la instancia de Express que monta el router de transacciones y el fichero de arranque del servidor. Es infraestructura no listada explícitamente en la "Estructura de ficheros esperada" de la spec, pero necesaria porque package.json ya declara main: src/index.js y los tests con Supertest requieren una app exportable sin levantar un puerto real.
Crea/modifica:
  - src/app.js: crea la app Express, monta src/routes/transactions.js, exporta la instancia (sin app.listen)
  - src/index.js: importa app.js y arranca el servidor con app.listen
NO tocar:
  - config/, .env, src/services/, src/validators/
Criterios de aceptación propios:
  - CA-4.1: src/app.js exporta una instancia de Express con el router de transacciones montado en /transactions/import
  - CA-4.2: src/index.js arranca el servidor reutilizando app.js, sin duplicar configuración de rutas
  - CA-4.3: la app exportada por app.js es utilizable directamente por Supertest sin necesidad de un puerto abierto
Depende de: TASK-3
```

```
TASK-5: Tests de aceptación
Descripción: Cubre cada criterio de aceptación de la spec (CA-1 a CA-7) con un test mínimo usando Jest + Supertest contra la app exportada en src/app.js.
Crea/modifica:
  - tests/transactions.test.js: un test por cada CA-1..CA-7
NO tocar:
  - src/routes/, src/services/, src/validators/ (solo se ejercitan mediante el endpoint)
Criterios de aceptación propios:
  - CA-5.1: test que cubre CA-1 (CSV completamente válido)
  - CA-5.2: test que cubre CA-2 (fila con campo vacío)
  - CA-5.3: test que cubre CA-3 (CSV vacío, solo headers)
  - CA-5.4: test que cubre CA-4 (archivo que no es CSV)
  - CA-5.5: test que cubre CA-5 (archivo >10MB)
  - CA-5.6: test que cubre CA-6 (amount no numérico)
  - CA-5.7: test que cubre CA-7 (1000 filas, top_5 exacto con empates)
Depende de: TASK-4
```
